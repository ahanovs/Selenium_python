# Selenium Portfolio

[![Selenium CI](https://github.com/ahanovs/Selenium_python/actions/workflows/ci.yml/badge.svg)](https://github.com/ahanovs/Selenium_python/actions/workflows/ci.yml)

UI-автотесты на Python + Selenium 4 для публичного учебного тренажёра
[ThreadQA XPath Practice Hub](https://lms.threadqa.ru/xpath-practice-hub).
Проект-портфолио fullstack QA: полный цикл — от чеклиста до CI, с осознанной
работой ИИ-агентов.

**Что внутри:** 43 автотеста на живом стенде (без моков) · 2 блока готово,
третий в работе · линт + тесты на каждый пуш и PR · ночной регресс ·
отчёты о каждом прогоне в Telegram · main защищён: мерж только через PR
с зелёными проверками.

## Зачем этот проект

- Полный цикл тестирования: чеклист → тест-кейсы → автотесты → трассировка
  кейс ↔ тест.
- Тесты идут по живому публичному стенду — без моков и заглушек, со всеми
  реальными сюрпризами (медленный стенд, гонки с фреймворком, локи браузера).
- Осознанная работа с ИИ: человек проектирует и принимает решения, агенты
  готовят черновики и ревьюят, CI проверяет объективно.

## Приложение под тест

**ThreadQA XPath Practice Hub** — тренажёр XPath/CSS: 16 страниц практики
(формы, кнопки и алерты, многошаговая форма, автокомплит, календарь,
таблицы, e-commerce, shadow DOM, iframe и другие). Без регистрации —
предусловия кейсов обычно «открыта страница X».

## Стек

Python 3.10 · pytest · Selenium 4 (драйверы через Selenium Manager) ·
GitHub Actions (ruff + pytest + ночной регресс) · Telegram-уведомления ·
Allure — по мере роста проекта.

## Конвейер работы с ИИ

1. Дизайн (чеклист, тест-кейсы) принимает человек; агенты готовят черновики.
2. Агент-ревьюер ревьюит дизайн в чистой сессии, без рассуждений автора:
   пропущенные классы сценариев, краевые значения, приоритеты.
3. Скиллы-агенты готовят болванки (Page Object'ы, фикстуры, каркасы тестов);
   локаторы, ожидания и ассерты — человек.
4. Код-ревью агента на флакоопасные паттерны + многократный прогон на
   стабильность.
5. CI — объективная верификация вместо ручного «глянул — ок».

Критерий каждого артефакта: могу объяснить решение без подглядывания.

  с PROJECT.md
- `.github/workflows/` — CI (ruff + pytest + Telegram) и stability-check
- `.githooks/` — pre-push гейт; включение: `git config core.hooksPath .githooks`

## Локальный прогон

```
pip install -r requirements.txt
python -m ruff check .
python -m pytest tests/ -q
git config core.hooksPath .githooks
```

Тесты идут по живому публичному стенду: Chrome открывается заново на каждый
кейс, полный прогон занимает ~20 минут. На CI тот же набор идёт на Ubuntu
примерно за 4 минуты.

## Роль ИИ

Фиксируется честно и дополняется по ходу проекта. Правила работы агентов —
в [AGENTS.md](AGENTS.md).

- **Человек** — автор и принимающий решения: правит и принимает черновики,
  пишет локаторы, ожидания и ассерты, финальное ревью, все коммиты.
- **ai-cheklistyor** — черновик чеклиста; **ai-test-keyser** — черновики
  тест-кейсов; **ai-avtomatizator** — болванки Page Object'ов, фикстур и
  каркасов тестов.
- **Агент-ревьюер** — ревью дизайна в чистой сессии; **код-ревьюер** —
  флакоопасные паттерны. Оба — разовые чистые сессии, не скиллы.
- **CI** — объективная верификация и отчёт в Telegram вместо ручного
  «глянул — ок».

Граница ответственности: дизайн ведётся по поведению стенда (чёрный ящик);
агенты не проектируют тесты «по коду» — чтение клиентского кода страницы
разрешено только на этапе ревью готового черновика.
