# Selenium Portfolio

[![Selenium CI](https://github.com/ahanovs/Selenium_python/actions/workflows/ci.yml/badge.svg)](https://github.com/ahanovs/Selenium_python/actions/workflows/ci.yml)

Второй пет-проект в портфолио fullstack QA: UI-автотесты на Python + Selenium.
Первый проект — pomidorqa-course-tests (Playwright + TypeScript).

## Цель

- Показать полный цикл: дизайн тестов (чеклист → тест-кейсы) → автоматизация → трассировка → CI.
- Показать осознанную работу с ИИ-агентами: человек автор и принимающий решения, агенты — ревью и болванки.

## Стек

- Python 3.10, pytest
- Selenium 4 (драйверы через Selenium Manager, без webdriver-manager)
- CI: GitHub Actions (ruff + pytest), отчёт о прогоне в Telegram
- Allure-отчёт — добавляется по мере роста проекта

## Приложение под тест

**ThreadQA XPath Practice Hub** — публичный учебный тренажёр XPath/CSS для Selenium:
https://lms.threadqa.ru/xpath-practice-hub

- 16 страниц практики: формы, кнопки и алерты, многошаговая форма, автокомплит, календарь,
  контекстное меню, таблицы, e-commerce, shadow DOM и iframe и другие.
- Без регистрации и авторизации — arrange через API и cleanup аккаунтов не нужны.
- Приоритет локаторов из AGENTS.md (`data-testid` первым) подтверждён замером DOM
  2026-10-06: на страницах практики ~300 `data-testid` (детали — в PROJECT.md скиллов,
  `.zcode/skills/`).
- Нюанс: стенд учебный, «реальных багов» ждать не стоит — фокус проекта на дизайне
  тестов, стабильности автотестов и отчётности.

## Конвейер работы с ИИ

1. Дизайн (чеклист, тест-кейсы) принимает человек; агенты готовят черновики.
2. Агент-ревьюер ревьюит дизайн в чистой сессии, без рассуждений автора: пропущенные классы
   сценариев, краевые значения, риски, оспаривание приоритетов.
3. Болванки (чеклист, тест-кейсы, Page Object'ы, фикстуры, каркасы тестов) готовят скиллы-агенты;
   правит, принимает и коммитит человек. Локаторы, ожидания и ассерты — человек.
4. Код-ревью агента на флакоопасные паттерны + многократный прогон на стабильность.
5. CI — объективная верификация вместо ручного «глянул — ок».

Критерий каждого артефакта: могу объяснить решение без подглядывания.

## Структура

- `tests/` — автотесты (pytest)
- `pages/` — Page Object'ы
- `docs/checklist.md` — чеклист (дизайн вперёд)
- `docs/test-cases/` — тест-кейсы в полном формате для критичных сценариев
- `CODEX.md` — кодекс автотестов: правила, которых требует ревью
- `.zcode/skills/` — скиллы ИИ-агентов (чеклистёр, тест-кейсер, автоматизатор) с PROJECT.md
- `.github/workflows/` — CI (ruff + pytest + Telegram) и stability-check
- `.githooks/` — pre-push гейт; включение: `git config core.hooksPath .githooks`

## Локальный прогон

- `pip install -r requirements.txt`
- `python -m ruff check .` — линт
- `python -m pytest tests/ -q` — тесты
- `git config core.hooksPath .githooks` — включить pre-push гейт на клоне

## Роль ИИ

Фиксируется честно и дополняется по ходу проекта: что написано человеком, что сгенерировано
агентами, какие решения приняты человеком. Правила работы агентов — в [AGENTS.md](AGENTS.md).

- **Человек** — автор и принимающий решения: правит и принимает черновики дизайна, пишет
  локаторы, ожидания и ассерты, финальное ревью, все коммиты.
- **ai-cheklistyor** (`.zcode/skills/`) — черновик чеклиста; **ai-test-keyser** — черновики
  тест-кейсов; **ai-avtomatizator** — болванки Page Object'ов, фикстур и каркасов тестов.
- **Агент-ревьюер** — ревью дизайна в чистой сессии; **код-ревьюер** — флакоопасные
  паттерны. Оба — разовые чистые сессии, не скиллы.
- **CI** — объективная верификация и отчёт в Telegram вместо ручного «глянул — ок».

Отступление от исходного плана, зафиксированное честно: по AGENTS.md дизайн пишет человек;
по решению от 2026-10-06 скиллы-болванщики готовят черновики чеклиста и кейсов, но авторство
и приёмка остаются за человеком — каждый пункт человек должен уметь объяснить без подглядывания.
