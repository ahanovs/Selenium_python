> ручная проверка или фиксация факта о стенде.

## Правила работы с этим файлом

- Автор — человек; агент-ревьюер ревьюит в чистой сессии, без рассуждений автора.
- Формат пункта: `- [ ] Проверка (P1|P2|P3)` — приоритет обязателен.
- Кейсы пишутся НА ОСНОВЕ пунктов, без 1:1: пункт может стать кейсом, частью
  кейса или ручным ориентиром (см. маршруты).
- Пункты с префиксом «Текущее поведение стенда:» — не требования, а документация
  фактического поведения: regression-замеры и защита автотестов от ложных ожиданий.
- После ревью: принятые пункты фиксируются, отклонённые — с причиной отказа.

### Допущения черновика (снять при ревью)

- Все пункты «Текущее поведение стенда:» подтверждены замерами 2026-10-06:
  реальные клики и ввод с клавиатуры в браузере, перехват `window.alert`,
  инвентаризация DOM. Замеры воспроизводимы.
- На странице нет тега `<form>` — нативная HTML5-валидация не срабатывает.
  Префикс и ссылка на общий корень введены по итогам ревью агента-ревьюера.
- Вставка текста через буфер обмена не проверялась — проверен только ввод
  с клавиатуры.
- Открытие внешней ссылки в новой вкладке следует из атрибута `target=_blank`
  (стандартное поведение браузера); переход кликом проверяется кейсом TC-013,
  до автоматизации вручную не выполнялся.
- Клик по подписи радио-кнопки не проверялся отдельно (связь label подтверждена
  той же, что у чекбокса).
- Кнопки раздела «Кнопки» без обработчиков и при заполненной форме — вероятно,
  намеренно (страница тренажёра локаторов), но подтверждено только поведением.
- Тултипы «Показать локаторы»: механизм открытия не подтверждён — пункта в
  чек-листе нет до уточнения.
- Время автозакрытия тостов по замеру ~3–4 секунды; точное время в кейсы не
  выносить без решения автора.
- Техническая деталь для автоматизации: при вводе без «@» поле Email (type=email)
  даёт `typeMismatch=true` — браузер распознаёт ошибку, но без `<form>` нигде её
  не показывает. В пунктах чек-листа отражается только видимое поведение.
