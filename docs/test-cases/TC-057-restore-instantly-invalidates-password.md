**ID:** TC-057
**Название тест-кейса:** НАХОДКА: restore мгновенно лишает аккаунт старого пароля
**Связанные требования:** Блок 4, пункт чек-листа: «НАХОДКА — restore мгновенно лишает аккаунт старого пароля без подтверждения владения почтой»
**Предусловия:** Стенд Bro AI API доступен: http://31.59.114.45:8000/api/v1. Создан РАСХОДНЫЙ аккаунт (уникальный email, валидный пароль); логин подтверждён.
**Шаги:**
1. POST /api/v1/jwt/create/ с кредами расходного аккаунта — проверить код (200)
2. POST /api/v1/users/restore/ с телом {"email": <email аккаунта>} — проверить код
3. POST /api/v1/jwt/create/ с теми же кредами — проверить код
**Ожидаемый результат:**
1) 200 — до restore пароль работает. 2) 200, пустое тело. 3) 401 — старый пароль немедленно недействителен. Зная только email, можно выкинуть пользователя из аккаунта (кандидат в баг-репорт).
**Приоритет:** High
**Статус:** Not Executed
**Примечания:** Замеры 2026-10-22. Аккаунт после кейса невозвратен (пароль убит, доступа к почте нет) — осознанный остаток по допущению чеклиста; НИКОГДА не вызывать restore на аккаунтах, нужных для уборки.
