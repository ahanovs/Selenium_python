**ID:** TC-035
**Название тест-кейса:** Правка имени после «Назад» обновляет сводку на шаге 3
**Связанные требования:** Блок 3, пункт чек-листа: «Изменение данных: после „Назад" правка поля и возврат на шаг 3 сводка показывает обновлённые значения» (P1)
**Предусловия:** Wizard на шаге 3 «Подтверждение», шаги 1–2 заполнены значениями из TC-032 (Chrome; десктоп; вьюпорт 1280×1600 через CDP)
**Шаги:**
1. Кликнуть «Назад» дважды (шаг 3 → шаг 2 → шаг 1)
2. Заменить имя на «Пётр Обновлённый» (полная замена значения, не дописывание)
3. Кликнуть «Далее» дважды — вернуться на шаг 3
**Ожидаемый результат:**
Сводка показывает обновлённые данные: имя «Пётр Обновлённый», старого имени нет; email и телефон — по одному разу, без дублей и искажений.
**Приоритет:** High
**Статус:** Not Executed
**Примечания:** История кейса: 2026-10-10 автотест зафиксировал «баг тренажёра» — задвоение email и телефона в сводке после правки имени; 2026-10-22 ручная проверка автора подтвердила, что сводка чистая — задвоение было артефактом автотеста (старая версия теста дописывала значения в React-поля вместо замены). Кейс возвращён к позитивной формулировке; пункт чек-листа, документировавший несуществующий баг, удалён.
