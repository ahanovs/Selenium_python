**ID:** TC-014
**Название тест-кейса:** Текущее поведение стенда: поля не проходят валидацию при вводе
**Связанные требования:** Блок 1, пункты чек-листа дословно: «Текущее поведение стенда: короткий пароль (менее 8 символов) не блокируется и не вызывает ошибки — minlength=8 вне формы не применяется (P2)»; «Текущее поведение стенда: значение без „@“ принимается в поле Email без сообщения об ошибке (P2)»; «Текущее поведение стенда: пустой email с атрибутом required не блокирует никакие действия (P2)»
**Предусловия:** Открыта страница https://lms.threadqa.ru/xpath-practice-hub/practice/basic-elements (Chrome, стабильная версия на момент прогона; десктоп; окно 1280×720); страница только что открыта, состояние сброшено
**Шаги:**
1. Ввести в поле «Пароль» значение «1234»
2. Ввести в поле «Email» значение «testexample.com»
3. Осмотреть поля и страницу рядом с ними
4. Очистить поле «Email»
5. Кликнуть кнопку «Успех» в разделе «Toast уведомления»
**Ожидаемый результат:**
В поле «Пароль» — маскирующие знаки в количестве 4; поле «Email» показывает testexample.com; рядом с полями и на странице нет сообщений об ошибке, длине или обязательности. При пустом «Email» появляется тост «Операция выполнена успешно!».
**Приоритет:** Medium
**Статус:** Not Executed
**Примечания:** Регрессионная фиксация текущего поведения (пункты чек-листа с префиксом «Текущее поведение стенда»): тест защищает от ложных ожиданий, а не от бага. Три проверки объединены сознательно — один класс «валидации нет» (общий корень: на странице нет тега form); в автотесте — параметризованный тест. Границы «ровно 500» и «7 символов» — тот же факт, отдельные кейсы не заводятся.
