**ID:** TC-014
**Название тест-кейса:** Текущее поведение стенда: поля не проходят валидацию при вводе
**Связанные требования:** Блок 1, пункты чек-листа дословно: «Текущее поведение стенда: короткий пароль (менее 8 символов) не блокируется и не вызывает ошибки — minlength=8 вне формы не применяется (P2)»; «Текущее поведение стенда: значение без „@“ принимается в поле Email без сообщения об ошибке (P2)»; «Текущее поведение стенда: пустой email с атрибутом required не блокирует никакие действия (P2)»
**Предусловия:** Открыта страница https://lms.threadqa.ru/xpath-practice-hub/practice/basic-elements (Chrome, стабильная версия на момент прогона; десктоп; окно 1280×1600); страница только что открыта, состояние сброшено
**Шаги:**
1. Выполнить действия из таблицы решений по строкам
2. Осмотреть поля и страницу рядом с ними после каждого действия
3. Перед строкой 3 очистить поле «Email» (или обновить страницу)
**Ожидаемый результат (таблица решений):**

| Поле | Ввод | Действие | Ожидаемый результат |
|---|---|---|---|
| Пароль | «1234» | ввод с клавиатуры | принято: 4 маскирующих знака; сообщений нет |
| Email | «testexample.com» | ввод с клавиатуры | принято, значение видно; сообщений нет |
| Email | (пусто) | клик «Успех» в «Toast уведомления» | появляется тост «Операция выполнена успешно!»; сообщений об обязательности нет |

**Приоритет:** Medium
**Статус:** Автоматизирован
**Примечания:** Регрессионная фиксация текущего поведения (пункты чек-листа с префиксом «Текущее поведение стенда»): тест защищает от ложных ожиданий, а не от бага. Общий корень всех строк: на странице нет тега `<form>`, нативная валидация required/minlength/type=email не срабатывает. Таблица решений — условия (поле × ввод) и действия; каждая строка — параметр автотеста. Три проверки объединены сознательно — один класс «валидации нет». Граница «7 символов» — тот же факт (валидация длины отсутствует), отдельный кейс не заводится.
