**ID:** TC-056
**Название тест-кейса:** restore: одинаковый пустой ответ для существующего и несуществующего email
**Связанные требования:** Блок 4, пункты чек-листа: «restore на существующий email → 200 с ПУСТЫМ телом» + «restore на несуществующий → ответ идентичен — существование не раскрывается» + «restore без email → 400»
**Предусловия:** Стенд Bro AI API доступен: http://31.59.114.45:8000/api/v1. Для ветки «существующий email» создан ОТДЕЛЬНЫЙ РАСХОДНЫЙ аккаунт (выведен из уборки: restore убивает его пароль — см. TC-057); отдельный заведомо несуществующий email.
**Шаги:**
1. POST /api/v1/users/restore/ с телом {"email": <email расходного аккаунта>} — проверить код и тело
2. POST /api/v1/users/restore/ с телом {"email": <несуществующий>} — проверить код и тело
3. Сравнить оба ответа между собой
4. POST /api/v1/users/restore/ с пустым телом — проверить код и тело
**Ожидаемый результат:**
1) 200, тело пустое. 2) 200, тело пустое. 3) ответы идентичны — существование аккаунта не раскрывается. 4) 400 {"error":"Email is required."} — кастомный формат ошибки.
**Приоритет:** Medium
**Статус:** Not Executed
**Примечания:** Замеры 2026-10-22. Отправка письма не проверяется (ручной ориентир). Основной тестовый пользователь (фикстура) restore в этом кейсе не затрагивает. Осторожно: не вызывать restore на аккаунтах, нужных для уборки (см. TC-057).
