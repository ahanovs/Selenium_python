**ID:** TC-048
**Название тест-кейса:** PATCH /users/me/ не меняет email (readOnly по контракту)
**Связанные требования:** Блок 4, пункт чек-листа: «PATCH /me email → по контракту readOnly; 200 без ошибки, email не меняется»
**Предусловия:** Стенд Bro AI API доступен: http://31.59.114.45:8000/api/v1. Пользователь зарегистрирован; access в наличии; исходный email известен.
**Шаги:**
1. PATCH /api/v1/users/me/ с телом {"email": "izmenyon." + исходный email}
2. Проверить код ответа и тело
3. GET /api/v1/users/me/ — проверить значение email
**Ожидаемый результат:**
200 без ошибки; в теле ответа и в повторном GET email остаётся исходным — поле игнорируется без сообщения об ошибке.
**Приоритет:** Medium
**Статус:** Not Executed
**Примечания:** Замер 2026-10-22. Тест закрепляет контрактное readOnly-поведение; при изменении поведения стенда — пересмотр. Подставляемое значение остаётся в границе контракта (не длиннее 50 символов), чтобы 200-без-изменений не смешивался с 400 по длине.
