**ID:** TC-017
**Название тест-кейса:** Поле «Имя» принимает специальные значения без искажений
**Связанные требования:** Блок 1, пункт чек-листа дословно: «Поле „Имя“ принимает „Ё“, эмоджи, разный регистр и значения с пробелами без искажений — значение хранится как введённое (P2)»
**Предусловия:** Открыта страница https://lms.threadqa.ru/xpath-practice-hub/practice/basic-elements (Chrome, стабильная версия на момент прогона; десктоп; окно 1280×1600); страница только что открыта, состояние сброшено
**Шаги:**
1. Ввести в поле «Имя» значение из таблицы (эмоджи — вставкой из буфера)
2. Проверить значение поля после ввода; для пробельных значений дополнительно проверить длину в DevTools ($0.value.length)
**Ожидаемый результат:**

| Ввод | Значение поля после ввода |
|---|---|
| «Ёлка» | «Ёлка» — без искажений |
| «😀😊» | «😀😊» — без искажений |
| «ПрИвЕт МИР» | «ПрИвЕт МИР» — регистр сохранён |
| «  y y  » | «  y y  » — пробелы до, после и двойные между словами сохранены |
| «     » (5 пробелов) | 5 пробелов — приняты как есть |

Ни для одного ввода не появляется сообщение об ошибке.
**Приоритет:** Medium
**Статус:** Автоматизирован
**Примечания:** Кейс автотестовый: проверка значений — через свойство value поля (Selenium `get_attribute("value")` возвращает актуальное свойство; пробелы на экране невидимы), ручной прогон — точечно по видимым значениям. В автотесте — параметризованный тест «ввод → значение» (таблица решений: одна проверка «принимает как есть», пять наборов данных). Эмоджи — частая причина реальных падений систем, «Ё» не входит в регулярку `[А-Я]`.
