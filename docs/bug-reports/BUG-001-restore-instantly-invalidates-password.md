**ID:** BUG-001
**Заголовок:** Restore мгновенно лишает аккаунт старого пароля без подтверждения владения почтой
**Severity:** Critical
**Priority:** High
**Окружение:** Bro AI API `http://31.59.114.45:8000/api/v1` (Django REST Framework), замер 2026-10-22
**Воспроизводимость:** всегда
**Предусловия:** Существующий пользователь с известными валидными кредами; доступ к эндпоинту `POST /api/v1/users/restore/` (неавторизованный).
**Шаги воспроизведения:**
1. Убедиться, что логин работает: `POST /api/v1/jwt/create/` с кредами → 200
2. `POST /api/v1/users/restore/` с телом `{"email": "<email пользователя>"}`
3. Повторить логин с теми же кредами

```bash
# 1. Логин работает
curl -sS -X POST "http://31.59.114.45:8000/api/v1/jwt/create/" \
  -H "Content-Type: application/json" \
  -d '{"email":"bugreport.001@test.ru","password":"S3c!Reveal7Qz"}'
# → 200 {"access": "...", "refresh": "..."}

# 2. Restore по email — без какого-либо подтверждения
curl -sS -X POST "http://31.59.114.45:8000/api/v1/users/restore/" \
  -H "Content-Type: application/json" \
  -d '{"email":"bugreport.001@test.ru"}'
# → 200, тело пустое

# 3. Логин со старым паролем
curl -sS -X POST "http://31.59.114.45:8000/api/v1/jwt/create/" \
  -H "Content-Type: application/json" \
  -d '{"email":"bugreport.001@test.ru","password":"S3c!Reveal7Qz"}'
# → 401 {"detail":"No active account found with the given credentials"}
```
При воспроизведении подставьте свой уникальный email: аккаунт после restore невосстановим.
**Ожидаемый результат:**
Старый пароль продолжает работать, пока владелец почты не подтвердит сброс переходом по ссылке/вводом кода из письма.
**Фактический результат:**
После шага 2 логин со старым паролем → 401. Пароль убит мгновенно, письмо владелец мог даже не получить. Любой человек, зная только email, одним запросом выкидывает пользователя из его аккаунта (DoS-класс), причём сам в аккаунт не попадает.
**Дополнительно:**
Ответ для существующего и несуществующего email идентичен (200, пустое тело) — существование аккаунтов не раскрывается, это сделано правильно.
**Доказательство:** автотест `test_tc057_restore_instantly_invalidates_password` (tests/api/test_users_api.py); кейс TC-057.
**Примечания:** вероятная причина — сброс пароля выполняется сразу на запрос restore, без токена подтверждения из письма.
