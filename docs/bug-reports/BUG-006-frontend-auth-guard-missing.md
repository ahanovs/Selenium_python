**ID:** BUG-006
**Заголовок:** Auth-guard фронта не закрывает прямые URL: после выхода /home отображает приложение
**Severity:** Minor
**Priority:** Low
**Окружение:** Фронт Bro AI `http://31.59.114.45:3000` (React SPA), замер 2026-10-23
**Воспроизводимость:** всегда (в профиле после UI-logout; на чистом профиле сверить)
**Предусловия:** Пользователь залогинен через UI; выполнен «Выйти из аккаунта» (редирект на /login).
**Шаги воспроизведения:**
1. Залогиниться через форму `/login`
2. Кликнуть «Выйти из аккаунта» → редирект на `/login`, тост «Вы вышли из приложения»
3. Прямым переходом открыть `http://31.59.114.45:3000/home`

```bash
# Шаги 1-2 — через браузер (UI-сценарий):
#   /login → заполнить Email/Пароль → «Войти» → /home/services
#   «Выйти из аккаунта» → /login + тост «Вы вышли из приложения»
# 3. В адресной строке открыть:
http://31.59.114.45:3000/home
# → URL остаётся /home, страница рендерит приложение целиком
```
**Ожидаемый результат:**
После выхода защищённые маршруты закрыты: прямой заход на /home редиректит на /login (или показывает страницу-заглушку без контента сессии).
**Фактический результат:**
Редиректа нет: URL остаётся `/home`, приложение рендерится целиком — «Добро пожаловать в Bro AI», сайдбар, баннер «Токены 1250», кнопка «Выйти из аккаунта». Auth-guard проверяет маршрут только при клиентской навигации, но не при прямой загрузке URL. Контент страниц — витринные мок-данные (без личной информации), поэтому Minor; непоследовательность при этом реальная: сам факт тоста «Вы вышли из приложения» показывает намерение закрывать сессию.
**Доказательство:** замер 2026-10-23 (браузерная сессия, DOM-снимок /home после logout); при автоматизации закрепится тестом кейса TC-064 (шаг 3).
**Примечания:** сверить на чистом профиле браузера; если на чистом профиле /home редиректит — сузить репорт до «стейл-стейт после logout в том же профиле».
