# Кодекс автотестов (Python + Selenium)

Открыл этот файл и чужой PR. Больше ничего не нужно.

Комментарий пиши так: `кодекс 5, time.sleep в тесте` — не «тут плохо».

Общие правила репозитория — в [AGENTS.md](AGENTS.md). Если пример в старом тесте
расходится с кодексом, следуй кодексу. Не копируй нарушение ради единообразия.

---

## 1. Где что лежит

```
tests/                  сценарий: кейсы, фикстуры, conftest
pages/                  экран: локаторы и действия (Page Object)
docs/checklist.md       чеклист (дизайн, человек)
docs/test-cases/        кейсы в полном формате, ID ↔ тесты
```

В тесте — кейс. В странице — «введи имя» и «нажми сохранить». В фикстуре — драйвер.
Не клади локатор в тест, если страница уже есть. Не клади сценарий в Page Object.

---

## 2. Как выносить

Повторилось два раза — выноси.

| Живёт в | Что туда |
|---|---|
| `tests/conftest.py` | фикстуры: драйвер, ожидания, общие предусловия |
| `pages/<экран>_page.py` | `open()`, поля, действия одного экрана |
| тест | подготовка, вызовы методов, ассерты |

Имя метода — смысл, не жест: `submit_form`, не `click_button_2`.

Ассерты из страницы не тащи. Страница действует, тест проверяет.

---

## 3. Каркас файла

Один файл `test_<экран>.py` — одна страница или фича. Не складывай форму и корзину
в один файл «на всякий случай».

```python
class TestBasicElements:
    """XPath Practice Hub — базовые элементы формы."""

    def test_tc001_valid_form_submit(self, driver):
        """TC-001: отправка формы с валидными данными."""
        ...
```

Общие фикстуры — в `conftest.py`, специфичные — рядом с тестами.

---

## 4. Имена и трассировка

Имя теста несёт ID кейса из `docs/test-cases/`: `test_tcNNN_<поведение>`.
Docstring дублирует формулировку кейса. Кейс без теста или тест без кейса —
незакрытая трассировка.

✅ `test_tc014_empty_password_shows_error`
❌ `test_1`, `test_check_button`

Не думай каждый раз заново. Открыл соседний тест — скопировал каркас.

---

## 5. Один тест или два

Один проверяемый факт на тест (AGENTS.md). Связанные проверки после одного действия —
один тест: имя и почта за одно «Сохранить» — ок.

Если чтобы проверить второе надо заново пройти половину шагов — режь на два теста.
Не плоди «проверить кнопку», «проверить текст», «проверить иконку».

---

## 6. Данные

Стенд публичный, без регистрации: arrange через API и cleanup аккаунтов не нужны.
Если сценарий меняет состояние страницы, сбрасывай его через `driver.refresh()`
в начале теста.

Данные, которые экран валидирует (email, имя), генерируй уникальными на прогон.
Пароль можно хардкодить.

---

## 7. Локаторы

Приоритет из AGENTS.md: `data-testid` → `id` → доступное имя/роль (`aria-label`, `role`) → CSS.
XPath — последнее средство, когда семантического локатора нет.

Замер DOM 2026-10-06: на страницах практики ~300 `data-testid` (`username-field`,
`email-field`, `country-dropdown`, `primary-button`), кроме:

- `autocomplete` и `context-menu` — по одному тестиду на страницу: бери `id`, `name`,
  `aria-label`;
- `shadow-dom-iframe` — тестиды есть и внутри shadow root, но XPath внутрь shadow DOM
  не работает в принципе: открывай `element.shadow_root` (Selenium 4), внутри — CSS.

Не выдумывай локатор по исходникам и не копируй непроверенный из старого теста:
открой страницу и подтверди локатор по реальному DOM.

---

## 8. Ждать и проверять

Никаких `time.sleep`. Только явные ожидания:

```python
WebDriverWait(driver, 10).until(EC.visibility_of_element_located(BasicPage.toast))
```

Не миксуй implicit wait с явным. Ожидай наблюдаемое состояние, а не «подожди и поверь».

В проверке — уже случившееся: «модалка открыта», не «модалка должна открыться».

**Клик с повтором по эффекту** — единственный разрешённый retry: живой стенд
иногда отдаёт страницу до гидратации React, первый клик уходит «в пустоту»
(элемент виден и получает фокус, но обработчиков ещё нет). Паттерн: клик →
ждём эффект 3 с → не появился, кликаем снова; общий лимит 15 с, после него —
честное падение. Оракул строго эффект (список открылся, тост появился), не
«кликнулся без исключения». Повторять клик вслепую, без эффекта-оракула, —
запрещено.

---

## 9. Шаги

Каждый осмысленный шаг и проверку оборачивай в `allure.step` с человеческим именем
(`allure-pytest` уже в requirements) — отчёт читается без исходников.

В степе-действии только действия Selenium: открыть, нажать, ввести, выбрать.
В степе-проверке только ассерты. Никаких кликов.

---

## 10. Ассерты

Ассерты осмысленные, без `assert True`. Сообщение в ассерте — формулировка ожидания:

✅ `assert "Success" in toast.text, "после отправки формы показывается тост успеха"`
❌ `assert page.is_ready()`, `assert True`

---

## 11. На ревью

Отдаём только зелёные. Красный PR — сначала себе.

Линт `python -m ruff check .` — ноль ошибок.

Новые и изменённые тесты — десятикратный прогон на флаки:

```bash
python -m pytest tests/<файл> --count 10 -q
```

Упал хотя бы один из десяти — найди причину и повтори все десять с начала.
Не прячь нестабильность за retry, повторным запуском «только упавшего» или ослаблением
ассерта.

В описании PR — что изменилось, не одна строка. Трассировка обновлена: ID кейса ↔ имя теста.
Свой флак чинит автор. Пустой LGTM без чеклиста не считается.
